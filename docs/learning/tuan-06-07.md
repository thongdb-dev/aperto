## Tuần 6

### Buổi 1 (~3h): Script seed + baseline không index

Làm seed **trước** khi học index — để có dữ liệu đo đạc, thấy tận mắt index nhanh hơn bao nhiêu.

**Làm:**

- [ ] Script `apps/api/scripts/seed.ts` (chạy bằng `ts-node` hoặc nest command): tạo **1.000 photographer** giả bằng faker — đủ đa dạng categories, service_area (toạ độ quanh HN/HCM/ĐN), giá package, rating giả
- [ ] Chạy thử query filter thô bằng `mongosh` khi **chưa có index**, đo bằng `.explain("executionStats")` — ghi `totalDocsExamined` và `executionTimeMillis` vào Nhật ký làm baseline

### Buổi 2 (~3h): MongoDB index

**Học (1.5h):** MongoDB docs — compound index, thứ tự field trong compound index (quy tắc ESR: Equality → Sort → Range), khi nào index vô dụng (query không dùng prefix của compound index, regex không anchor, `$ne`).

**Làm (1.5h):**

- [ ] Thiết kế index cho các query search dự kiến: ví dụ `{categories: 1, "price": 1}`, text/regex cho tên
- [ ] Chạy lại `explain()` sau khi thêm index → so với baseline, ghi số liệu vào Nhật ký (đây là mục ✅ của tuần)
- [ ] Thử một query **cố tình không dùng được index** và giải thích tại sao qua explain (`COLLSCAN` vs `IXSCAN`)

### Buổi 3 (~3h): Geo query

**Học (1h):** `2dsphere` index, GeoJSON Point, `$near` vs `$geoWithin`.

**Làm (2h):**

- [ ] Đổi `service_area` trong `photographer_profiles` sang GeoJSON Point (cập nhật cả seed), tạo `2dsphere` index
- [ ] Query "photographer trong bán kính X km quanh toạ độ Y" chạy được trong mongosh trước, rồi mới đưa vào API

### Buổi 4 (~3h): Aggregation pipeline — API search

**Học (1h):** `$match`, `$lookup`, `$sort`, `$skip/$limit`, và đặc biệt `$facet` để đếm tổng + lấy trang dữ liệu trong **1 query**.

**Làm (2h):**

- [ ] `GET /search/photographers`: filter khu vực (geo hoặc city), thể loại, khoảng giá, phân trang, sort theo rating
- [ ] Dùng `$facet`: nhánh `results` (skip/limit) + nhánh `total` (`$count`) — trả `{ items, total, page }`
- [ ] `$lookup` sang `packages` để lọc theo khoảng giá (hoặc denormalize `min_price` vào profile — chọn 1, ghi trade-off)

**Tự vấn:** `$near` có dùng được trong `$facet` không? (không — geo phải là stage đầu; thiết kế pipeline theo ràng buộc này).

## Tuần 7

### Buổi 5 (~3h): Availability calendar

**Làm:**

- [ ] Model lịch: collection `availability` (photographer_id, date, status `available`/`blocked`) hoặc lưu mảng ngày block trong profile — chọn theo hướng "ngày nào cũng rảnh trừ khi bị block"
- [ ] API photographer tự block/mở ngày; logic **tự động block** ngày đã có booking `confirmed` (M4 sẽ gọi vào đây — giờ viết sẵn hàm, test bằng cách chèn booking giả)
- [ ] Filter "ngày trống" cắm vào API search: loại photographer đã kín ngày được chọn

### Buổi 6–7 (~6h): FE — trang search

**Làm:**

- [ ] Trang `/search`: bộ filter (khu vực, thể loại, giá, ngày) — **state đồng bộ lên URL query string** để share link được (`useSearchParams` / `router.replace`)
- [ ] Infinite scroll bằng `useInfiniteQuery` (React Query) + `IntersectionObserver`
- [ ] Calendar chọn ngày (MUI DatePicker), disable ngày photographer bận trên trang chi tiết
- [ ] Card kết quả: ảnh cover từ portfolio (M2), giá từ, rating

**Tự vấn:** khi filter đổi, `useInfiniteQuery` cache key phải đổi theo — key thiết kế thế nào để back/forward trình duyệt vẫn đúng?

### Buổi 8 (~2h): Tổng kiểm chứng

- [ ] Seed 1.000 photographer, search + filter phản hồi **< 200ms local** (đo bằng thời gian response, log ra hoặc dùng tab Network)
- [ ] Với từng query của API search: chỉ ra index nào được dùng qua `explain()` — dán kết quả vào Nhật ký
- [ ] Share 1 link search có filter cho chính mình qua tab ẩn danh → mở ra đúng trạng thái filter
- [ ] Nhật ký: số liệu trước/sau index; quyết định denormalize `min_price` hay `$lookup`; thiết kế availability
