## Tuần 10

### Buổi 1 (~3h): Auto-tạo project + timeline events

**Làm:**

- [ ] Schema `projects` + `timeline_events` (mảng nhúng: `{type, actor_id, payload, at}`) theo [docs/04-data-model.md](../04-data-model.md)
- [ ] Hook vào transition `confirmed` của M4: tạo project, ghi event đầu tiên `project_created` (FR-PROJ-11)
- [ ] Helper `logTimelineEvent(projectId, type, ...)` — mọi module sau (upload, selection, delivery, payment) sẽ gọi vào; thiết kế type là union string rõ ràng
- [ ] `GET /projects/:id` + guard **thành viên project**: chỉ customer/photographer của booking gốc truy cập được — viết `ProjectMemberGuard` dùng lại được cho mọi route con

### Buổi 2 (~3h): WebSocket lý thuyết + gateway đầu tiên

**Học (1.5h):** WebSocket vs HTTP: handshake Upgrade, kết nối giữ lâu dài, server push. Socket.IO: room, broadcast, namespace; tại sao cần Redis adapter khi chạy nhiều instance (instance A phải phát được tới client nối vào instance B). NestJS Gateways docs.

**Làm (1.5h):**

- [ ] `ChatGateway` với `@WebSocketGateway`; **auth ở handshake**: client gửi JWT trong `auth` payload, verify trong `handleConnection`, fail → disconnect ngay
- [ ] Event `join_project`: verify là thành viên project (dùng lại logic guard Buổi 1) rồi mới `socket.join(room)`
- [ ] Test bằng script Node nhỏ (socket.io-client): token sai → bị đá; token đúng nhưng không phải thành viên → không join được room

### Buổi 3 (~3h): Chat server hoàn chỉnh

**Làm:**

- [ ] Schema `project_messages`; event `send_message`: lưu DB trước → broadcast tới room (kèm id thật + created_at từ server)
- [ ] REST `GET /projects/:id/messages?before=<cursor>` phân trang **cursor-based** (before + limit) cho scroll ngược — không dùng skip/limit (tin nhắn mới chèn liên tục làm skip lệch)
- [ ] Cắm Redis adapter (`@socket.io/redis-adapter`) dùng Redis sẵn có — chạy thử 2 instance API (2 port) chứng minh message xuyên instance

## Tuần 11

### Buổi 4–5 (~6h): FE chat — phần khó nhất project

**Làm:**

- [ ] Socket client trong React: connect kèm JWT, tự reconnect, join room theo project đang mở (cleanup khi unmount)
- [ ] **Optimistic update**: gửi tin → hiện ngay với id tạm + trạng thái "đang gửi" → server ack → thay bằng bản thật; lỗi → đánh dấu gửi lại
- [ ] **Phân trang scroll ngược**: `useInfiniteQuery` với cursor `before`, prepend trang cũ **giữ nguyên vị trí scroll** (đo scrollHeight trước/sau khi prepend)
- [ ] Typing indicator: emit `typing` (throttle), tắt sau 3s không gõ
- [ ] Dedupe: tin của chính mình về qua broadcast không được hiện 2 lần

**Tự vấn:** tin nhắn realtime đến khi đang xem trang cũ (đã scroll lên) — append vào đâu? Hiện nút "N tin mới ↓"?

### Buổi 6 (~3h): Moodboard + Checklist

Phần "dễ thở" giữa module — CRUD đơn giản, tái dùng những gì đã có.

**Làm:**

- [ ] Checklist: mảng item nhúng trong project `{title, done, assignee}` — CRUD + tick, ghi timeline event
- [ ] Moodboard: tái dùng **nguyên pipeline upload M2** với `photos.type = 'moodboard'`; grid ảnh tham khảo 2 bên cùng thêm
- [ ] Tab layout trong Project Workspace (FE): Conversation / Moodboard / Checklist / Galleries / Delivery — routing lồng nhau

## Tuần 12

### Buổi 7–8 (~6h): Luồng ảnh RAW → Selection → Edited

Luồng nghiệp vụ chính giữa 2 vai trò:

**Làm:**

- [ ] RAW Gallery: photographer upload (pipeline M2, `type='raw'`, đếm dung lượng vào giới hạn 5GB/project theo Q6 — giờ **enforce**: quá 5GB từ chối presign)
- [ ] `photo_selections`: customer chọn ảnh + comment yêu cầu chỉnh sửa; status `selected → editing → delivered`
- [ ] Edited Gallery: photographer upload bản edit, link với selection tương ứng
- [ ] Mỗi bước ghi timeline event; FE: gallery có checkbox chọn, badge số ảnh đã chọn, ô comment per-photo

### Buổi 9 (~3h): Delivery — watermark + signed URL

**Học (30'):** signed GET URL có expiry (khác presigned PUT ở M2 thế nào — cùng cơ chế ký, khác method và mục đích).

**Làm:**

- [ ] Watermark: worker BullMQ dùng `sharp().composite()` đóng logo lên ảnh delivery khi **chưa thanh toán đủ** (trạng thái thanh toán tạm mock bằng flag trên project — M6 sẽ nối thật)
- [ ] Link tải: API cấp signed URL hết hạn **24h**, chỉ cấp cho thành viên project; tải cả album = job nén zip (hoặc trả danh sách URL — chọn 1, ghi lý do)
- [ ] Timeline event `delivery_ready`

### Buổi 10 (~2h): Tổng kiểm chứng

- [ ] Mở 2 trình duyệt 2 tài khoản (customer + photographer): chat real-time mượt, optimistic update không nháy, typing indicator chạy
- [ ] Script socket.io-client với user **ngoài project** → join room bị từ chối (đây là bài test bảo mật đầu tiên của bạn — lưu script lại)
- [ ] Đi trọn luồng: booking → confirmed → project tự sinh → upload RAW → chọn ảnh + comment → upload edited → delivery có watermark → mock "đã thanh toán" → tải bản sạch qua signed URL, đợi URL hết hạn → 403
- [ ] Nhật ký: các quyết định (cursor pagination, zip vs list URL), bug khó nhất của FE chat và cách sửa
