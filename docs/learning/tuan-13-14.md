## Tuần 13

### Buổi 1 (~3h): Stripe test mode + PaymentIntent đầu tiên

**Học (1.5h):** stripe.com/docs/payments — PaymentIntent lifecycle (`requires_payment_method → processing → succeeded`), test cards (4242…), Stripe CLI: `stripe listen --forward-to localhost:4000/api/v1/payments/webhook`.

**Làm (1.5h):**

- [ ] Tạo tài khoản Stripe test mode, cài Stripe CLI
- [ ] `PaymentModule`: tạo PaymentIntent bằng script trước (currency `vnd`, amount là số nguyên đồng — kiểm chứng zero-decimal), xác nhận bằng test card trên trang docs

### Buổi 2 (~3h): Schema payments + luồng deposit

**Làm:**

- [ ] Schema `payments` theo [docs/04-data-model.md](../04-data-model.md): `type` (deposit/milestone/final/refund), `commission_amount`, `transaction_ref`, `status`
- [ ] Booking `confirmed` + policy có deposit → `POST /payments/deposit-intent`: tính số tiền từ `policy_snapshot` (hàm `calculateDeposit` M4), tạo PaymentIntent, lưu payment `pending` với `transaction_ref = paymentIntent.id`
- [ ] Metadata của PaymentIntent chứa `booking_id`, `payment_id` — webhook sẽ cần

### Buổi 3 (~3h): Webhook handler — idempotent từ dòng đầu tiên

Phần quan trọng nhất module. Học kỹ trước khi code.

**Học (1h):** tại sao webhook bắn trùng (Stripe retry khi không nhận 2xx, network lỗi giữa chừng); tại sao phải **verify chữ ký** (`stripe.webhooks.constructEvent` với raw body — NestJS cần bật `rawBody: true`); out-of-order events.

**Làm (2h):**

- [ ] `POST /payments/webhook`: verify chữ ký → sai trả 400
- [ ] Xử lý `payment_intent.succeeded`: **check `transaction_ref` + status trước khi ghi** — đã success rồi thì trả 200 luôn, không ghi lần 2 (đây là idempotency)
- [ ] Cập nhật payment → ghi timeline event → nếu là deposit đầu tiên, đánh dấu booking đã đặt cọc
- [ ] Luôn trả 2xx nhanh; việc nặng (email, tính toán) đẩy vào queue

**Tự vấn:** check-then-write có race không nếu 2 webhook trùng đến cùng lúc? (có — dùng unique index trên `transaction_ref` + type, hoặc `findOneAndUpdate` với điều kiện status; chọn 1 và giải thích).

### Buổi 4 (~3h): Commission + milestone + final

**Làm:**

- [ ] Hàm thuần `calculateCommission(amount)` = 10% (Q4), làm tròn VND nguyên — kèm unit test; `commission_amount` ghi vào từng payment
- [ ] Milestone payment theo `policy_snapshot.milestones`; final payment = phần còn lại
- [ ] View "số dư payout" của photographer = tổng success − commission − refund (chỉ cần con số đúng, chưa cần payout thật ở v1.0)

## Tuần 14

### Buổi 5 (~3h): Refund flow + nối với M4, M5

**Làm:**

- [ ] Huỷ booking → `calculateRefund` (M4) → tạo Stripe Refund → payment mới `type='refund'`, webhook `charge.refunded` cập nhật status
- [ ] **Mở khoá delivery**: khi tổng thanh toán success ≥ tổng giá booking → thay flag mock ở M5 bằng logic thật → ảnh delivery hết watermark, cấp signed URL bản sạch
- [ ] Dispute (M8 sẽ làm UI) — giờ chỉ cần: booking `disputed` thì chặn tạo payment mới

### Buổi 6 (~3h): Test webhook handler — bộ ba bắt buộc

**Làm (mock Stripe SDK, không gọi mạng trong unit test):**

- [ ] Bắn trùng: cùng event 2 lần → DB chỉ 1 giao dịch, lần 2 vẫn trả 200
- [ ] Sai chữ ký: `constructEvent` throw → 400, DB không đổi
- [ ] Out-of-order: `charge.refunded` đến trước khi refund được ghi nhận local → xử lý không crash (bỏ qua an toàn hoặc tự tạo bản ghi — chọn và test theo lựa chọn)

**Làm:**

- [ ] Huỷ booking có cọc theo policy `before_x_days` còn hạn → refund về đúng số `calculateRefund`
- [ ] Nhật ký: cách chống race trong webhook đã chọn; những gì học được về zero-decimal VND
